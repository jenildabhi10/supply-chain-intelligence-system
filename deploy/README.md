# Deployment guide

The project deploys as **two free services**:

| Component | Host                       | URL pattern                          |
| --------- | -------------------------- | ------------------------------------ |
| Frontend  | Vercel                     | `<project>.vercel.app`               |
| API       | HuggingFace Spaces (Docker)| `https://<user>-<space>.hf.space`    |

This split keeps the Next.js build on Vercel's edge for fast page loads while
the heavier Python + ML runtime sits on HF Spaces' generous always-on free tier
(no sleep-on-idle like Render).

---

## 1. Deploy the API to HuggingFace Spaces

### One-time setup

1. Create a free HF account at https://huggingface.co/join.
2. Create a new Space:
   - **SDK:** Docker
   - **Hardware:** CPU basic (free)
   - **Visibility:** Public
   - **Space name:** e.g. `sci-api`
3. Add **Repository secrets** in the Space settings:
   - `GROQ_API_KEY` — from https://console.groq.com
   - `NASA_FIRMS_MAP_KEY` — from https://firms.modaps.eosdis.nasa.gov/api/

### Push the code

The HF Space is just a git repo. From your project root:

```bash
# clone the empty space
git clone https://huggingface.co/spaces/<user>/sci-api hf-space
cd hf-space

# copy the API-only artefacts (NOT the frontend)
cp -r ../src .
cp ../config.py ../requirements.txt ../bootstrap.py ../scheduler.py .

# copy the HF-specific Dockerfile + space README
cp ../deploy/hf-space/Dockerfile .
cp ../deploy/hf-space/README.md .

# trained model artifacts (generated by `python bootstrap.py` locally)
mkdir -p models data
cp -r ../models/* models/
cp -r ../data/gold data/   # only the Gold features parquet, not raw bronze

git add .
git commit -m "Initial deploy"
git push
```

The Space will build the Docker image and start serving on port 7860 (HF
default). It maps automatically to `https://<user>-sci-api.hf.space`.

### Verify

```bash
curl https://<user>-sci-api.hf.space/health
# {"status":"ok","model_loaded":true,"llm_available":true,...}
```

## 2. Deploy the frontend to Vercel

### One-time setup

1. Sign up at https://vercel.com/signup with your GitHub account.
2. Click **New Project** → **Import** the GitHub repo.
3. **Important:** set the Root Directory to `frontend/`.
4. Add an Environment Variable:
   - `NEXT_PUBLIC_API_BASE` = your HF Space URL (e.g. `https://<user>-sci-api.hf.space`)
5. Click **Deploy**.

### Subsequent deploys

Every push to `main` triggers a Vercel build automatically. No manual step.

### Custom domain (optional)

In Vercel project settings → Domains → add your domain. Vercel handles HTTPS.

## Notes on HF Spaces

- **Cold start:** ~30s first hit after a deploy. Subsequent hits warm.
- **No sleep:** unlike Render free tier, HF Spaces stay running.
- **Memory limit:** 16 GB on the free CPU tier — plenty for our model + DuckDB.
- **Build time:** first Docker build is ~5 min (xgboost, pandas, shap). Cached afterwards.
- **Logs:** view in the Space's "Logs" tab.

## Troubleshooting

**API returns 503 "model not loaded":** The bootstrap step hasn't run.
You need to commit the `models/` directory contents to the HF Space repo
(they're trained artefacts, not code, and small enough to fit in git LFS or
even directly).

**Vercel build fails:** Most likely the Root Directory isn't set to
`frontend/`. Project Settings → General → Root Directory.

**Frontend shows "API offline":** Check `NEXT_PUBLIC_API_BASE` env var in
Vercel — must include `https://` and have no trailing slash.
